# ChatGPT sign-in investigation

2026-10-31. OpenAI documents [Sign in with ChatGPT](https://developers.openai.com/siwc/quickstart) for eligible open-source apps, including optional use of an eligible user's ChatGPT plan for Responses API requests. Identity sign-in alone does not grant inference permission or access to the user's API key. This is a possible future provider, not an implemented connection.

The [open-source flow](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) requires a loopback listener on `127.0.0.1`, PKCE, state and nonce validation, ID-token verification, a separately granted inference scope, and protected storage and refresh of credentials. The [official example](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt) keeps credentials and requests in a local main process. The inference path uses the Responses API; SimplySF2e currently runs in a browser and uses Chat Completions. A browser-only module on a remote Foundry VPS cannot itself create the required listener on the GM's computer or use an owner-protected local credential file.

An integration therefore needs a suitable local companion or another OpenAI-documented flow compatible with the deployment. It must keep each GM's credentials isolated, implement the documented sign-in and token lifecycle, and adapt the request/streaming format to Responses. Do not expose a GM's token to other Foundry users or silently route it through the VPS. Verify applicable availability, deployment requirements and live behavior before implementing; this investigation does not establish that a browser-only implementation is supported.
