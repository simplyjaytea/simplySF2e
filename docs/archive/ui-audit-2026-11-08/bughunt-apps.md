## Looked at, found sound
- Busy/double-click: every Create/Generate/Reroll/Discard sets `#busy` synchronously before its first await; Create during the one-click late step is guarded by `#busy` in `#onCreateActor`/`#createCharacterActor`/`#createEncounterActors`; Discard re-checks busy and the on-screen preview identity after its confirm; Open/Forget Recent are blocked by busy and `#createPending`.
- Catch blocks: `#refineArchetypeSpells`, `#refinePCLoot`, the extra PC purchase pass, and the create-time `selectChoices` all rethrow `cancelled`/`runLimit`. Failures set `#error`, null the half-built preview and render in `finally`. Cancel/close path (`close()` confirm, `_cancelGeneration`, late `render()` dropped by `_closed`) is consistent. `reuseRunSignal` is used only for the choice-round and apply continuation; the budget window is not reopened there.
- Creation commit ordering: creature, PC and encounter creation consume the draft only after verify; rollback of unverified actors, encounter all-or-nothing rollback with survivor report; `moveToGeneratedFolder` never throws. Shop/treasure null `actor` only after verify, then delete on failure.
- Listeners: `_onRender` listeners all bind to elements inside the re-rendered part (no duplicates after re-render); the frame-level keydown/wheel listeners bind once per frame (`_keysElement`); Welcome/Sources/Manage-presets listeners are per-render on fresh nodes.
- Escaping: no `{{{ }}}` in any template; chat whispers (`#whisperStatCheck`, `manualNotesContent`, bug-report dialog, delete confirms) use `esc`/`escAi`; `progress.detail` is set via `textContent`.
- i18n: scripted check of every `game.i18n.format/localize` literal key against lang/en.json (placeholders both ways) found no mismatch; dynamic keys (Tokens.*, Skills.*, Loadout.*, StatCheck.Band*, Mode.*, Threat.*, TreasureAmount.*, Role.*, Rarity.*, Treasure.Amount*) all exist.
- Settings/keys: API and Jev keys are client-scope; apps never log or render a key (only `hasApiKey` booleans); bug report redacts configured keys; all world-setting writes (sources, presets, welcome/whatsnew) sit behind `canOpenApps()` GM check. Presets import/export, runPool, recent-generations, generator-memory, progress math: no defect found.
- Existing tests run clean: app-base, generator-app.review, generator-app.uistate, itemforge-app.lifecycle.
