# T-AUDIT-C: setup and information windows (Provider Setup, Sources, Welcome, What's new)

Read-only audit against `.claude/skills/ui-ux/references/anti-slop-checklist.md`. Worktree `/root/sf2e-wt/T-AUDIT`. Harness PNGs were read from `tools/ui-preview/out/`; they were not regenerated.

Fixtures viewed: all 25 at `@720` and `@460`. `@460-short` viewed for welcome-fresh, welcome-error, provider-setup-price-error and sources-default. The other `-short` renders were not opened one by one. Their full-height `@460` renders show no overflow, and the short renders checked scroll cleanly.

Contrast: computed with WCAG relative luminance from the tokens in `styles/simplysf2e.css`. The translucent surfaces were composited over `.window-content` `#0c1620`. Values:
- `--spf-text-muted` on a card (`--spf-surface-raised`, about rgb 23,41,57): 10.5:1.
- `--spf-brand-accent` on a card: 9.7:1.
- `--spf-danger-fg` on a card: 6.7:1.
- `--spf-success-fg` on a card: 7.0:1.
- Placeholder (muted at 0.7) on `--spf-console`: 5.9:1.
- `--spf-control-border` on a card: 4.4:1.
- Accent note on a selected tile: 6.5:1.
- Muted note on a harness button: 7.2:1.
- `.spf-primary` label on the top of its gradient: **4.50:1**, exactly at the limit.
- `--spf-border` on a card: 2.5:1. It is used only as a card frame, not as a control edge.

No text pair in these windows fails 4.5:1.

## 2. Already right (do not regress)

1. **Error-holding section opens itself.** Provider Setup forces Cost estimate open when there is a price error (`pricesOpen: this.#priceError != null || …`, `provider-setup-app.mjs:136`). The section gets a red left edge, and the summary states "Needs a fix" with an icon, not colour alone (provider-setup-price-error). The Jev section opens when TypeSafe is active or a Jev key is saved.
2. **Collapsed sections still show their state.** The fold summaries read "Not set: provider-reported cost only", "$0.27 in · $1.10 out per 1M tokens" and "TypeSafe AI · key saved" while closed.
3. **Selected state has a non-colour cue.** Provider presets and Welcome tiles use `aria-pressed`, bold weight and an inset border. Sources rows use an accent left rail plus the checkbox.
4. **One shared focus ring.** `:is(button,input,select,textarea,summary):focus-visible` in `simplysf2e.css` covers every control. The primary button drops its clip-path on focus so the ring is not cut. Sources rows outline the whole label on `:has(input:focus-visible)`.
5. **Icon-only buttons are labelled.** The new and delete connection buttons carry `aria-label` + `data-tooltip`. Decorative icons consistently carry `aria-hidden="true"`.
6. **Sources Save/Reset stay pinned.** Save and Reset stay in view while the list scrolls (sources-default@460-short). `scroll-padding-block-end` keeps the focused checkbox clear of the bar.
7. **The filter does not lose work.** Filtering only hides rows, and the no-match message says ticked packs stay ticked (sources-no-match). The status line "Showing 2 of 20 packs · Clear filter" is `aria-live`.
8. **What's new keeps old notes out of the way.** Older notes fold under one "Earlier changes (8)" disclosure with a count, are styled quieter (border-colour rail), and are absent from the automatic view.
9. **Narrow layouts use the window, not the viewport.** All narrow rules are `@container spf-window`, never viewport `@media`. No fixture scrolls sideways at 460. Reduced motion stops `.fa-spin` and the progress animations.
10. **Copy names cause and next step in most places:** `Sources.NoMatches`, `ProviderSetup.PriceInputInvalid`, `JevCorsWarning`, `Welcome.SampleHint` ("nothing is created until you click Create"), `Welcome.ApiKeyHint`. No "simply / seamlessly / Oops" in any of the four prefixes.

## 3. Cross-window consistency against the Generator (generator-empty-monster@720, generator-empty-attention@720)

- **Disclosure.** The Generator "Advanced options", the Provider Setup folds and "Earlier changes" all use `.spf-disclosure` with a chevron. The Welcome "Advanced" is the only one without (#8).
- **Selected tile.** The Generator mode tab shows selection with a violet mode-accent border and no glow. Welcome and Provider Setup tiles use a cyan border plus magenta `--spf-neon-glow` and a text-shadow. These are two treatments of the same "selected option" control (#1).
- **Legend chips.** The Generator "Creature concept" legend matches the Provider Setup and Welcome chips. The Sources legends use a magenta-tinted edge, tighter letter-spacing and an outer glow frame (#19).
- **Same state, two wordings.** Missing compendium content reads "Required compendium content is unavailable: Spells, Feats. Configure Compendium Sources before generating." in the Generator (with a gear button beside it). Welcome says "Missing: Spells. Open Compendium Sources and enable a pack for each." with no button in view (#5). One string, or at least one pattern, should serve both.
- **Warning and error boxes.** The Generator auth warning, the Welcome readiness warning and the Provider Setup CORS warning all use core `.notification warning`, which is consistent. The Generator status rows use a 3px `--spf-warning` left rail instead. Field-level errors use the Provider Setup `.spf-field-error` (red text + icon). Run errors use the Generator `.spf-error-notice`. Welcome connect errors use `.notification error`. `.notification` has no module styling at all (`grep` finds none in `styles/`), so its look in a world comes from Foundry core, not from the harness stub in `tools/ui-preview/harness.css`.
- **Spacing scale.** The Generator body uses `gap: --spf-space-md; padding: --spf-space-xs`, and so do Sources and What's new. Provider Setup and Welcome use `gap: --spf-space-lg; padding: --spf-space-sm`, so the two setup windows breathe more than the tool window. Choose one.
- **Secondary buttons.** The Generator uses `.spf-secondary` ("Preview Plan"). The setup windows' secondary buttons are bare `<button>`s (core-styled). This is acceptable, but `.spf-secondary` in the shared kit is then used in only one window.
- **Button casing.** The Generator and Provider Setup use Title Case ("Preview Plan", "Load Models", "Save & Authorize", "Set Up AI Connection", "Check Again"). Welcome mixes in sentence case ("Compendium sources", "Generate a sample monster"), as do Sources ("Reset to defaults") and What's new ("Don't show for updates"). Pick one; Foundry core buttons are mostly Title Case.

## 4. Unverified

- **§1 "compare against a published sf2e NPC sheet":** no sheet render is available in the harness.
- **§5 contrast of core-styled controls:** button fill, button border, checkbox and select chevron are styled by Foundry core, not by the module. The harness stub border `#50606c` on a card is 2.3:1, but that number says nothing about the real Foundry look. `.notification` box colours are also core.
- **§5 focus:** visibility and tab order were not checked. No JS runs, and I did not open the saved `.html` in a browser. Tab order is inferred from DOM order only, which matches visual order in all four templates.
- **§5 "no motion beyond Foundry's own":** the indeterminate `<progress>` animation (welcome-connecting) is a browser default and is not covered by the module's reduced-motion rule. Its real behaviour in Foundry's Electron/Chromium was not checked.
- **§4 unsaved edits (#11):** I did not trace whether `provider-setup-app.mjs` has dirty-state tracking it could expose.
- **§3 toast copy:** `ModelsLoaded`, `ModelsFailed`, `Saved*`, `TestFailed`, `Jev*` and the `Sources.Saved` / `ResetDone` toasts appear outside the window. I read them in `lang/en.json` (they name cause and next step), but none is visible in any fixture.
- **§6 icons:** every glyph used rendered in the harness, so none is Pro-only. I did not separately check that Foundry's bundled FA version resolves `fa-plug-circle-check` (FA 6.1+).
- **What's new window icon:** `tools/ui-preview/render.mjs` has no `whats-new` icon entry, so the harness header shows none. The app sets `fa-solid fa-bolt`, so this is a harness gap, not a module bug.
- **Typography:** no Foundry core CSS (Signika) in the harness, so not judged.
- **`-short` renders:** only welcome-fresh, welcome-error, provider-setup-price-error and sources-default `@460-short` were opened. The other provider-setup and welcome `-short` renders were not viewed individually.
