## 2. Already right (do not regress)

1. **Narrow tables.** At ≤520 px Shop folds the Type column into a muted second line under the item name, Level becomes "Lvl" with the full label kept visually hidden for assistive tech, names wrap by word, and the remove × buttons stay in one centred column (`shop.css`/`treasure.css` `@container`, `simplysf2e.css` l.886-923).
2. **Numeric columns** are right-aligned and `nowrap`, and the headers align with them. The Treasure leftover "Credits (Credstick)" row is visually set apart and not removable.
3. **Labels.** Every input has a visible `<label>`; nothing is placeholder-only. The Shop level helper sits directly under its field and is linked by `aria-describedby`.
4. **Token report.** It is collapsed, but its summary always shows total and cost, including "at least … (some requests reported no cost)", so the run cost is never hidden (§4).
5. **Item Forge kind switch.** The selected state has a non-colour cue (`aria-pressed`, frame, bold text, underline bar), the selected kind's description sits beside it via `aria-describedby`, and `:focus-visible` gives a 2 px ring.
6. **Focus ring** is defined once for `button, input, select, textarea, summary`, and the primary button drops its clip-path while focused so the ring is not cut (`simplysf2e.css` l.243-254).
7. **Icon-only buttons** carry `aria-label`s that include the row name ("Remove {name} from stock", "Delete preset {name}"), and decorative icons are `aria-hidden`.
8. **Manage Presets Delete** is tinted red and separated by a divider and gap from Edit/Duplicate/Export. Long preset names ellipsize without breaking the row.
9. **Create is disabled with a visible reason** when nothing is left: Shop shows "Every item was removed…" and Treasure falls back to credits-only.
10. **Short-window reachability.** Every 460-short render reaches the action footer by scrolling, and no sideways page scroll appears. Reduced-motion turns off every module animation.
11. **Error notices** keep "Copy bug report" inside the error they report, and the Authorize action comes before the endpoint detail.

## 3. Cross-window consistency notes

- **Status bar.** Item Forge, Shop and Treasure share it verbatim: a connection switch or name, the model, last-run text, test/configure buttons, a state icon, then a full Compendium Content row. Only the `*.SourcesDetail` sentence differs. The Generator differs: it folds Compendium and Jev into a one-line `Compendium ✓ Ready · Jev ✓ On` disclosure (see #14). Manage Presets has no status bar, which is correct for a non-AI dialog.
- **Progress.** All three windows use `_progress.hbs` unchanged and put it under the form, next to Generate. The step labels come from each app. Item Forge's fixture steps ("Scanning published items", "Drafting the item", "Resolving components") are not the real `ItemForge.Progress*` strings ("Finding published passive effects", "Item concept", "Pricing & validation"), so the fixture drifts from the copy a GM sees (same issue type as #33).
- **Form order.** Item Forge and Shop put the prompt first and the options below. Treasure puts the options first and the optional Theme prompt last, with `rows="2"` against 3 elsewhere. That order is defensible because Theme is optional, but it is the only window that differs. Item Forge stacks the Level label above the stepper, as Shop and Treasure do. The Generator puts "Level" inline to the left.
- **Generate button.** Item Forge reuses the Generator keys ("Generate" / "Generate another version"); Shop and Treasure name their object ("Generate shop" / "Generate another shop"). Pick one pattern.
- **Footer.**
  - Generator: Create actor / Reroll Loot (a distinct action) / Discard.
  - Item Forge: Create item / Discard.
  - Shop: Create merchant / Discard.
  - Treasure: Create hoard / Reroll (the same action as Generate, #6) / Discard.
  - Manage Presets: New preset (primary) / Export all / Import, with a top divider (`.spf-hud-actions`); the other windows have no divider.
- **Level chip.** "Creature 4" (Generator), "Item 6", "Shop 3", "Party level 4". Treasure's chip is longer and wraps under the title at 460. Acceptable.
- **Accent.** The Generator tints the status-bar border and header rule per mode (violet for Monster). The three other windows fall back to the brand cyan. The Generator's mode switch uses uppercase labels; Item Forge's kind switch uses sentence-case labels.
- **Placeholders.** Generator "e.g. a cult…" (lowercase after e.g.), Item Forge "e.g. A scorched…", Shop and Treasure no "e.g." (#21).
- **Preview `<section>` aria-label.** Shop and Treasure have it; Item Forge does not (#31).
- **Window titles.** "SimplySF2e — Generator" and "SimplySF2e — Item Forge", against "SimplySF2e Shop" and "SimplySF2e Treasure" (#24).
- **Level minimum.** Shop allows 0; Item Forge and Treasure use 1 (fixtures `minLevel`). This is probably intentional (level-0 gear) but undocumented in the UI. The Shop hint "Stock is this level or lower" covers it.

## 4. Unverified

- **§1 "compare against a published sf2e NPC sheet at the same width"**: no sheet screenshot was available. Without Foundry core CSS, typography and core `button`/`select` chrome (Discard, Export all, Import, Use my party) cannot be judged.
- **§3 "warning has an icon or a word" when core CSS applies**: the harness substitutes its own `.notification` borders (`tools/ui-preview/harness.css` l.24-27). I do not know whether Foundry core adds a glyph to `.notification.warning/error` (#4).
- **§5 contrast**: computed from tokens, not picked from PNG pixels. Not checked:
  - text over the primary gradient, other than its two end stops (4.50:1 at the top stop is right at the limit);
  - the disabled-button `opacity: 0.55` state (exempt from WCAG, but about 4.2:1 computed for muted text);
  - the `#98503d` attention left-edge, about 2.7:1 (computed). It is backed by the ⚠ icon, so it is not colour-only.
- **§5 focus order and visible focus**: no module JS runs in the harness and the saved `.html` was not opened in a browser, so focus rings, tab order and tooltips (`data-tooltip`, full model name, truncated preset `title`) were not exercised.
- **§3 numeric alignment**: tabular figures depend on what Foundry's `--font-monospace` resolves to (#17).
- **§6 icon sizing from one token**: no icon-size token exists, so I could not confirm icons share a size. The icons seen are FA6 Free solid except `fa-sword` (Pro) and the `fa-regular fa-circle` mix (#7).
- **Rarity chip in table rows** (`spf-shop-rarity`, `spf-treasure-rarity`): no fixture row sets `rarity`, so chip wrapping at 460 is unseen.
- **Bug-report button on user-fixable errors** (`shop-error`, `treasure-error` show "Copy bug report" for NoCandidates): the fixture sets `canReportBug: true`. I did not trace whether `_canReportBug` is true for that error in the app.
- **Fixtures not opened individually**: itemforge-empty-armor/augmentation/crystal (both widths), itemforge-weapon-preview@460-short, armor@720, crystal@720, augmentation@460, shop-busy@720, shop-error@460, shop-empty-attention@720, treasure-busy@460, treasure-error@720, treasure-all-removed@720, treasure-empty-attention@720, treasure-preview-level@460.
