# simplySF2e playbook

The one file every agent (Claude, Codex, anything else) reads first. It holds where the project stands, the rules, how to run things, how work is delegated and reviewed, and the traps already found. CLAUDE.md and AGENTS.md only point here. The user-facing guide is README.md. Older material lives in `docs/archive/` and is not needed for normal work.

**Update this file at the end of every session:** rewrite §1 "Where we are", and add durable lessons to §8. Keep it short; move anything finished or historical to `docs/archive/`.

## 0. Start here

1. **Coordinator:** read §1 to §3 and §6, then other sections as the task needs. **Worker or reviewer:** follow your prompt and read §3, §4 and §8.
2. `git log --oneline -10` and `git status`. Git is authoritative for branch state, not any file.
3. Baseline: run the all-tests command in §4.
4. If §1 lists a review in flight, check whether its PR merged mid-review. If it did, ship fixes as a **new** PR.
5. End every session with the tree clean or committed on a named branch, never with uncommitted work on `main` or `next`.
6. **Release policy (JT, 2026-11-08):** nothing merges to `main` per batch. Reviewed batches land on the local integration branch **`next`**; `main` gets one PR when a build is worth live-testing, or when JT asks. See §3.6 and §6.

## 2. The project

Foundry VTT module `simplysf2e`. An AI generates Starfinder 2e NPCs/monsters, encounters, player characters, magic items, shops and treasure from a text prompt. Every named pick is grounded against the real installed `sf2e` compendium. Repo `simplyjaytea/simplySF2e`. Targets system **`sf2e` 1.6.0+** (cited against tag `sf2e-1.6.1` of the pf2e repo, Foundry 14.361 min / 14.369 verified). The 1.5.1→1.6.1 diff changed no pack ids; it added the Tech Core classes Mechanic and Technomancer.

**Glossary.**
- **sf2e system**: built from the PF2e monorepo branch **v14-dev**. Pack ids are `sf2e.<packs[].name>`. "Real source" = that repo's TS/JSON fetched live: `https://raw.githubusercontent.com/foundryvtt/pf2e/v14-dev/<path>`.
- **Actor / Item**: a character or creature sheet, and anything embedded on one.
- **Compendium / pack**: a library of real game content. A pick either matches a real document or is marked custom.
- **GM Core**: *Starfinder GM Core* Building Creatures / Treasure by Level tables, cited in `tables.mjs` (Chapter 2, pp. 116–128). Never invent a table number.
- **ABC item**: the Ancestry, Background and Class items a PC embeds; a **Heritage** comes from its own pack. A **Grant** is an item that bundles others via `system.items`.
- **Rule Element (RE)**: a JSON rule in `system.rules`. A wrong key fails **silently**.
- **Spellcasting entry**: the item holding a caster's spells and slots (`system.prepared.value` = `prepared|spontaneous|innate|focus`). **Focus pool**: 1–3 points for class spells, separate from slots.
- **Slug**: `ghost-touch`. PF2e sometimes needs **camelCase** (`ghostTouch`) instead; they are not interchangeable.

## 3. Invariants (never break)

1. **Clone a real Rule Element from a published item; never hand-author one.** No hand-written fallback exists, by design.
2. **Use real v14-dev sf2e source when a field name or shape matters.** Never recall PF2e shapes. The coordinator fetches it and pastes the quoted lines into worker prompts; workers use only those; reviewers spot-check the citation. This has bitten the project repeatedly.
3. **The in-module AI never emits a number or writes code.** It picks scale words and enum slugs; the module supplies values from tables, real documents or pre-written macro bodies.
4. **Escape AI text before HTML** with `text.mjs` `esc`/`toHtml` (descriptions, actor notes, macro chat).
5. **Fail closed.** Drop an unresolved pick with `console.warn`; never guess. Exceptions: a PC feat slot or a PC caster's spell list, where empty is worse than approximate. The exception never widens legality (JT, 2026-11-10): an ancestry or class feat slot with no feat of its own trait stays empty and is listed in the review panel, and a Mystic or Witchwarper with no tradition proven from its connection or paradox gets no class spell entry. Skill completion may use labeled key-ability defaults; budgets, schedules and unsupported mechanics are never guessed.
6. **Never push or merge to `main` directly.** Branch + PR (GitHub enforces it since 2026-11-10: `main` requires a pull request with a passing `verify`). A merge to `main` auto-publishes a public **beta** release (beta-manifest installs update), so batches do **not** go to `main` one by one: they merge into the integration branch **`next`** (local, mirrored to `origin/next` as a backup; pushing a branch triggers no workflow). One PR `next` → `main` only when the coordinator judges the accumulated work worth a live test, or JT asks. Promoting to **stable** (every install) is a separate, deliberate Release dispatch.
7. **Design choices go to JT first:** UX, scope, balance numbers, and anything this file does not already decide.

## 5. Architecture and file map

Three actor/item pipelines over shared compendium and table code, plus the Shop, Treasure and setup windows. Reskin is a Generator mode, not a separate window.

**NPC / creature** (`builder.mjs`, the most tested path): `generateConcept()` in `ai.mjs` (one call on `systemPrompt()`, scales not numbers) → `normalizeConcept()` → spells (`chooseSpellFocus` → `getSpellCandidates` → `selectSpells`) → equipment (`getEquipmentCandidates` → `selectEquipment`) → feats/abilities/loot grounded to bounded real catalogs → `resolveConcept(..., { exactContent: true })` builds a completion manifest; an unresolved required pick blocks Create → `createActor()` clones real items and verifies persisted sources. Published picks keep their exact issued source references; a bespoke ability is either an Area Blast/Aura template (module-built from a published scaffold, numbers from tables; `ability-templates.mjs`) or narrative-only; the 7 blank glossary abilities are filled per level (`ability-fill.mjs`). After Create, `stat-check.mjs` compares the sheet with GM Core bands and only reports (it whispers the GM when something is off). Loot reroll is one small `generateLoot()` call. The art and token structure come from the closest bestiary creature (`art.mjs` `findBestiaryScaffold`). Encounter mode: `designEncounter()` sets a theme and per-role briefs, then runs the creature pipeline per member (N× the prompt cost), 3 at a time, or 1 at a time on a local provider (`pool.mjs`). Elite/Weak (Alien Core pp. 204/207) is applied once through the system's `adjustment`. **Reskin** mode: the GM drops an NPC; the AI writes new fiction and may rename strikes/abilities by id; stats, rules, traits and items are unchanged unless the GM re-levels the copy (`relevel.mjs`; it also rebuilds module-built abilities from their `flags.simplysf2e.built` provenance), and renamed items keep their original slug (`pf2eSluggify`).

**Player character** (`pc-builder.mjs`): no math layer. It embeds real ABC/heritage/feat items with correct `system.build` data and the system derives AC/HP/saves itself. `normalizePCConcept()` → `resolvePCConcept()` → `createCharacterActor()`. Single class; no pre-create edit screen.

**Item Forge** (`item-builder.mjs`, `rule-templates.mjs`, `itemforge-app.mjs`): passive items reuse unchanged rules from published `sf2e.equipment` (`getForgeEffectCatalog`); 1/day activations use pre-written macros (`macro-templates.mjs`). Weapons and armor clone a real base, set a native `system.grade` and install real upgrades in `system.subitems`. The system derives price and level.

## 6. How work runs

JT's standing rules (2026-11-08, procedure revised 2026-11-10). Claude Code only. One coordinator session; the workers are **subagents the coordinator starts with the Agent tool**, each in its own git worktree, each on the model that fits the task. The herdr terminals (below) are the alternative when JT wants long-lived worker sessions. This section is the workflow as actually run on 2026-11-10 (two batches, 22 worker branches, landed the same day); the prompt templates are the exact shape used.

| Role | Model | Does |
| --- | --- | --- |
| Coordinator | the Claude Code session JT talks to, Fable 5.2 | Plans; verifies every finding against the code before it becomes a task; looks up sf2e/Foundry source and pastes the quoted lines into prompts; creates worktrees; writes every prompt; dispatches; **reads every diff**; integrates the batch branch itself (merges, conflict resolution, wording fixes, QA rows, What's new, docs); runs the release check and the UI harness; lands on `next`. Writes code only for one-line fixes and table corrections it has verified itself. |
| Hard pieces, UI design-build | Opus 5.5 subagent | Concurrency and state (connection queue, form-state plumbing, the AI request layer), cross-file PC logic, and every visual change (it runs the harness and views its own PNGs against the anti-slop checklist). |
| Logic fixes | Sonnet 5.5 subagent | A fix that needs a pack-data check and a new test: game math, resolve/build decisions, caches, localisation moves, release notes. |
| Mechanical fixes | Haiku 5.5 subagent | A change the prompt can pin to an exact line: a guard, an attribute, a string table, a format. Never anything with more than one code path. |

**Rules of the procedure.**
- **Verify before dispatch.** A reviewer's finding is a lead. The coordinator opens the cited lines and, where pack data decides it, checks the pinned cache (`tools/class-bench/cache`) before writing a task. One R3 finding (upgrade slots) was a false alarm that only the worker's data check exposed: tell workers to investigate first when the data shape is unproven.
- **JT's calls go to JT as cards.** Anything under invariant 7 (UX, scope, balance numbers, wording style, a GitHub setting) is asked with the AskUserQuestion tool: one self-contained question per card, two to four options, the recommended one first, a preview when layouts are compared. Dispatch everything that does not depend on the answer first, then ask. Record each decision in the worker prompt as "Owner decision (JT, date)".
- **One worktree per task, disjoint files.** `git -C /root/simplySF2e worktree add /root/sf2e-wt/<ID> -b work/<ID> <base>`, then set identity `jt` / `jt_f@ymail.com`. Ids: `R<n>-<TOPIC>` for a review round, `T-<TOPIC>` otherwise. When two tasks must touch one file, name in both prompts which methods each owns and say "change only these lines, no reformatting"; the coordinator resolves what still collides.
- **Waves.** Wave 1 off `next`. The coordinator merges finished branches into `work/<ROUND>-BATCH` as they arrive and cuts later waves off that batch branch, so a later task builds on earlier fixes (shared files: `lang/en.json`, `generator-app.mjs`, `provider-setup-app.mjs`, `pc-builder.mjs`).
- **At most six subagents at a time** (one or two Opus, two or three Sonnet, up to three Haiku). Send every dispatch of a wave in one message; they run in the background and report on completion. Never poll.
- **The worker proves its own fix.** Every prompt requires: a failing test before the fix where practical, `node --check`, the all-tests loop with no FAIL, `git diff --check`, and a mutation run in a scratch copy (`cp -r` under the session scratchpad, never the worktree, never a symlink to `/root/simplySF2e`) showing the new test fails without the fix. UI tasks run the harness and view their PNGs at 720, 460 and 460-short.
- **Review.** The coordinator reads every production diff before merging (tier 3 for all; a full read for `tables.mjs`, `relevel.mjs`, stat math, pack ids, enums, REs, PC grants/slots, connection and key handling). It views the PNGs of every UI branch. A defect goes back to the builder as a new commit, or the coordinator fixes a one-liner on the batch branch and says so in the commit. Spawn an independent Sonnet reviewer only for a diff the coordinator cannot fully judge. (The Haiku → Sonnet → coordinator ladder below still applies when herdr terminals build.)
- **Reports.** Each worker writes `/root/sf2e-wt/reports/<ID>.md` (branch, SHAs, files, evidence with quoted lines, tests, mutation result, live checks for the GM, unverified items) and ends with a ten-line summary. `ls /root/sf2e-wt/reports/<ID>*` before reusing an id.

**Lifecycle.**
1. **Review or plan:** goal, stop condition, files each task may touch. For a review round: four read-only reviewers by area plus the coordinator on manifest, workflows, entry point and the UI harness; then verify the top findings in the code.
2. **Decide:** cards to JT for every design call; dispatch the independent tasks meanwhile.
3. **Split and dispatch:** worktrees, prompts from the template, one message per wave.
4. **Merge as they land:** read the diff, `git merge --no-ff work/<ID>` into `work/<ROUND>-BATCH`, run the all-tests loop after each merge (a test in one branch can pin source text another branch changed: fix the pin on the batch branch).
5. **Integrate (coordinator):** QA rows in `docs/qa-checklist.md` (one new section per round), one What's new entry per GM-visible theme at the top of `RELEASE_NOTES` (2 to 5 bullets each, ids never renamed), button names and quoted strings updated in README and docs, PLAYBOOK §1/§8/§9, `docs/next-qa.md`.
6. **Gate:** `git fetch origin main && bash tools/release-check.sh --no-ui`, then the harness directly (`cd tools/ui-preview && npm install && npm install --no-save playwright@1.64.1 && SPF_SHOOT_FREEZE=1 node shoot.mjs`); view a few merged PNGs.
7. **Land:** `git merge --no-ff work/<ROUND>-BATCH` into `next` in `/root/simplySF2e`, rerun the all-tests loop, `git push origin next` (backup only; no workflow fires), remove the worktrees and `work/*` branches.
8. **Milestone PR to `main`:** only when JT asks or the coordinator judges a live test worth it (§3.6). `main` is protected: the PR needs a passing `verify`; read `Benches` too. Body lists every id in `docs/next-qa.md`; merging publishes one beta; clear `next-qa.md`.
9. **Hand off:** rewrite §1, add lessons to §8.

## 7. Verified against real source — do not re-litigate

The first four bullets are PF2e-era checks inherited with the builders (re-verify if the schema area is reworked); the rest were checked against v14-dev sf2e between 2026-10-01 and 2026-10-25.

- Setting all five `build.attributes.boosts` tiers regardless of level is safe (`character/document.ts` slices by `allowedBoosts`).
- A PC spellcasting entry's `proficiency.value` is a floor, not a cap (`spellcasting-entry/document.ts` takes `Math.max` with `base-spellcasting`).
- `details.languages.value` is not truncated; the system adds Int mod to `build.languages.max`.
- Never write grade-derived values (grade credits, grade level) into a graded/runed item's `system.price`/`system.level`. `physical/document.ts` `computeLevelRarityPrice()` derives both on every prep from the stored base price and level (`physical/helpers.ts:38-39,61`, sf2e-1.6.1), so keeping the cloned base's own values is correct, and adding grade values would double-count (re-verified 2026-10-25, `tools/pipeline-bench/FORGE-REPORT.md`).
- A PC's focus pool needs no rule: `resources.focus.max` resets to 0 each prep and each embedded non-cantrip focus spell adds 1, capped at 3 (`item/spell/document.ts`, `creature/document.ts`; re-verified 2026-10-02). An NPC pool is plain actor data. Mystic, Witchwarper and Technomancer have focus spells. A Technomancer's initial magic hack is not GrantItem'd by the data; `pc-support.mjs` maps each programming language `_id` to its hack (cited from each language's description, tag `sf2e-1.6.1`).
- Credits/UPB: `ActorInventory.addCurrency` clones bundled `credstick.json`/`upb.json`; the credit amount is `system.price.value`. No sf2e gold-piece UUIDs exist.
- G1 skills: sf2e adds `computers` (int) and `piloting` (dex) (`src/scripts/config/index.ts`). NPC core skills are written to `system.skills.<slug>.base`, never as lore items (`item/lore.ts` appends `-lore`).
- Spell consumables are spell **gems**, not scrolls (`config/spell-consumables.ts`).
- The rest hook is still `pf2e.restForTheNight` in v14-dev; no `sf2e.` variant exists.
- Module art: the system's own `moduleArt` map (`system/module-art.ts`) only registers `pf2e.*` packs, so sf2e creatures get art-module art through Foundry core `CompendiumArt`. Core `CompendiumArt` injects that art into compendium documents, so a scaffold's `img`/`prototypeToken.texture` already carry it. This is inferred from core's type docs (core JS isn't public); if it ever fails, the creature falls back to the sf2e default art. The system default actor art is `systems/sf2e/icons/default-icons/<type>.svg` (`actor/base.ts` `getDefaultArtwork`), which is also what every sf2e NPC ships.
- Creature data snaps to published values: speeds and sense ranges to the 452 NPCs of the seven creature packs; generated casters get 3 slots per rank (`NPC_SLOTS_PER_RANK`); Recall Knowledge follows GM Core pg. 54; narrative abilities with dice/DC/HP text are dropped; a strike named after a carried weapon takes that weapon's damage, traits and range.

- sf2e glossary (`sf2e.bestiary-ability-glossary-srd`) ships 7 abilities with blank values (`@Damage[(0)`, `dc:` empty, `dc=0`, `Rupture [0]`, `<p>0 feet.`, `[Size]`/`[Listed …]`, Aura radius 0); published NPCs always fill them per creature (`/root/sf2e-wt/reports/I-ZERO.md`). GM Core has no rule for Rupture, aura distance or size limits; the Alien Core ability glossary entries are not on AoN. GM Core pg. 128: creature ability DCs use the Spell DC table; pg. 129: aura DC usually moderate; pg. 128 Area Damage table (unlimited/limited), checked against two independent AoN fetches.

- Aura rule: v14-dev `src/module/rules/rule-element/aura.ts` accepts `{key:"Aura", radius}` alone (radius clamped 5-240, rounded to 5; `traits`, `effects` default empty; slug defaults from the item); it only draws the aura and registers `actor.auras` — saves/conditions are not automated without `effects`. Same-slug auras on one actor merge (names are made unique per creature).
- Currency has no system cap (v14-dev, fetched 2026-11-08): `item/physical/coins.ts` constructor floors and abs each denomination with no maximum; sf2e `toString` prints `Math.ceil(copperValue / 10)` plus "credits" as plain digits (no gp normalisation, no thousands separator); `item/treasure/document.ts` reads a Credstick's stored `sp: N` back as N credits; `actor/inventory/index.ts` `addCurrency` merges credits unbounded; `actor/sheet/base.ts:343-344` wealth totals use the same path. `CURRENCY_ITEM_MAX` (5,000,000 since 2026-11-08) is the only ceiling. Equipment grade labels: `static/lang/en.json` `PF2E.Item.Physical.Grade.<slug>` = Commercial, Tactical, Advanced, Superior, Elite, Ultimate, Paragon (the module's `ItemForge.Grade*` keys mirror them).
- Foundry 14 `Notifications` (pf2e v14-dev `types/foundry/client/applications/ui/notifications.d.mts`, fetched 2026-11-08): `NotificationOptions` has `localize`, `format` (values passed to `Localization#format`), `escape` ("whether to escape the values of `format`") and `clean` ("clean the provided message string as untrusted user input; no cleaning is applied if `format` is passed and `escape` is true..."). Defaults are not in the types. The module's standard since BATCH-4: any AI name or provider error text goes `ui.notifications.X(KEY, { localize: true, format: { name }, escape: true })`, never a pre-formatted string; `generator-app.races.test.mjs` scans the source for it.
- Enricher patterns (v14-dev `src/scripts/hooks/init.ts`): `@(Check|Localize|Template)[...]`, `@(Damage)[...]` with nested brackets, `[[/act ...]]`; Foundry core adds `@UUID`/`@Embed`/`@Compendium` and `[[/r]]`. A U+200B after `@` / `&` and between `[[`/`]]` (`inertProse`) stops all of them.

## 8. Traps and lessons

Each line is a bug class that already cost a fix. The full story is in `docs/archive/history-pf2e.md`.

**Foundry / system data (silent failures)**
- A wrong pack id (`pf2e.*` instead of `sf2e.<name>`), RE key, or slug vs camelCase matches nothing and fails quietly. Check the real source.
- Runtime-built translation keys look unused to `i18n-keys.test.mjs` (§4). The 2026-10-25 cleanup nearly deleted two live ones; the tier-1 review caught it.
- PC feat placement: slot feats set `system.location` to `<group>-<level>` (Free Archetype: `archetype-<level>`, category still `class`); ABC-granted feats use the granting item's `_id` (`pc-builder.mjs`).
- Attribute boosts live on each ABC item (`boosts[*].selected`, `keyAbility.selected`), applied by `assignItemBoosts`/`resolveKeyAbility`; skill increases follow the class's own `skillIncreaseLevels`.
- Background Lore is an embedded `type: "lore"` item at rank 1. NPC core skills are `system.skills.<slug>.base`.
- Item pre-create hooks shift current HP, so set PC HP to the derived max after embedding. Awaiting embedded creation does not settle detached `_onCreate` rule updates.
- `GrantItem.preselectChoices` skips option predicates: keep predicate exclusions, and leave predicated or dynamic choices to native prompts (`choice-set.mjs`). A finished create does not mean every choice is answered; report unresolved hints.
- Graded property-rune keys put the grade first (`greaterFlaming`; use `propertyRuneKey`). Exclude fundamental runes from property candidates or they are priced twice (`runes.mjs`, legacy path).
- A scaffold token's `name` and `texture` are copied onto the new actor; set the name and keep mapped token art (`createActor`, `reskin.mjs`).

**Pipeline safety**
- Exact-reference resolvers check the issued candidate identity plus pack. Pack membership alone lets a forged `{packId, _id}` through.
- A run-level limit is not a step failure. `AIRequestError.runLimit` must be rethrown by every catch that otherwise degrades gracefully (`refineSpells`, `refineCreatureAbilities`, `refineCreatureFeats`, `refineEquipment`, `refineLoot`, `choice-set`'s callback, the generator's choice rounds), or a budget/deadline hit continues the run and commits a half-built actor with a generic message. Same for `cancelled`.
- A deadline armed inside a timer that every stream chunk resets is not a deadline. Arm one absolute timer per request; a keep-alive stream otherwise outlives it forever. Test it with a chunked SSE stub, not a silent socket, and race the assertion against a watchdog so a regression fails fast instead of hanging CI.
- A continuation step inside one run (`_beginProgress(..., { reuseRunSignal: true })`) must not open a second budget window, or spent tokens reset every choice round.
- Offline AI tests pass vacuously when the production selector early-returns (no wishlist → no request). Every fixture must assert result content, the request count, and a prompt/catalog fragment in the request body, or it is decoration.
- Mutate each production check the suite claims to protect and confirm the suite goes red. A negative fixture built by removing several keys at once hides which check it covers; compose it from a known-good payload and change exactly one leaf.

**Tools and CI**
- A manual tool's fixed arguments must be validated offline. Call every task entry against a stubbed provider and fail on a `TypeError`; otherwise a signature drift shows up as "this model is bad" in the matrix.
- A benchmark gate fails on **FAIL**, never on WARN: WARN is the documented steady state (class-bench alone is 31 WARN). `class-bench/run.mjs` needed an explicit `process.exitCode` before CI could gate on it.
- Never add a blind retry to a POST on a network error: the request may already have been received and billed. Retrying a rejected GET is safe; that is the only place `retryNetworkErrors` is used.
- A cost report must price prompt and completion separately from their own counts. Averaging the two prices and multiplying by the total is silently wrong.
- Clear a draft only after writes verify; roll back only documents this run created; a retry must not duplicate actors.
- Each run owns an AbortSignal. `Cancelled` is never retried or reported as a timeout. Parse AI JSON with string-aware brace matching; a `length` truncation fails closed; reasoning-channel text is never the answer; the final SSE record can arrive at EOF.
- An explicit empty AI selection is a valid answer, not a failure. Candidate lists have fixed ceilings and are never expanded to fit.
- API keys never live in world settings and are bound to their exact endpoint; no key goes over plain http to the internet (`settings.mjs`).
- Macro bodies cannot import helpers: they embed a fixed `escHtml` and receive pre-escaped names (`macro-templates.mjs`).

- Build test inputs with the production normalizer (`normalizeConcept`, the stat builder), never hand-written post-normalize objects. FIX-B's resolve check required a strike `damage` field that concept strikes never have, so every Trample would have been dropped; the tests passed because their fixtures carried `damage`. Assert the shape the check really sees.
- When a pick is checked early (resolve) and built later, both must run the same decision. Two hand-kept checks drift; dry-run the build function at resolve instead.
- A "longer, clearer" copy change can break layout: T-ERR's `Party.None` text widened the Generator by 172 px through a `min-width: max-content` row. Run the UI harness on any batch that changes GM-visible strings, not only on template/CSS changes.
- `ai.creatureFidelity.test.mjs` forbids naming published abilities in the creature prompt. Describe behaviour, not names.

- A TUI agent may sit on a dialog (idle-session, permission, compact) after long idle; `hc send` then reports `started:false`. The coordinator must not answer another agent's prompt (auto-mode blocks it, rightly); route the task to a subagent instead and tell JT.
- Reviewers repeatedly caught bugs whose tests used fixture shapes production never produces (Trample damage, selector `{name, candidate}` refs, cost total-only usage). Every new feature gets one end-to-end test through the real normalizer, the real candidate list and a selector stub with the production return shape.
- QA row ids are global: pick a free prefix (`grep -n "^| <id>\." docs/qa-checklist.md`) and run `release-check.sh` — it catches duplicates.
- One Claude Max account feeds all five terminals and every subagent. Keep Haiku tasks small, spawn Opus only for UI/UX or planning, and stagger heavy runs (benches, harness) so one burst does not stall the others.

- Task ids get reused across sessions: `/root/sf2e-wt/reports/` still held a 2026-11-06 `T-COST*` set when a new T-COST ran on 2026-11-08. Before dispatch, `ls /root/sf2e-wt/reports/<ID>*`; pick a fresh id or move the old files to `reports/archive-<date>/`.
- `hc wait <t>` returns at once when a terminal ended its turn with Claude Code Monitors still running (status `done`, turn unchanged); the agent resumes only when its monitor fires, which it may never do. Watch for the report file instead (`until [ -f /root/sf2e-wt/reports/<ID>.md ]; do sleep 5; done` in the background) and nudge the terminal with the fact it is waiting for when the condition is already met.
- Two reviewers writing `<ID>-T2.md` collide: a fresh tier-2 subagent for a Sonnet-built branch writes `<ID>-T2i.md`. Name the fresh reviewer in the batch prompt for every branch Sonnet built; on 2026-11-08 the coordinator forgot and the lead engineer caught it itself.
- A literal that looks like a copy of a constant may be a separate silent clamp on another path: tying builder.mjs's `100000` to `CURRENCY_ITEM_MAX` also lifted the ceiling on NPC/PC coin padding from level 13 up. Tier 2 caught it (2026-11-08). When a task says "align literals to the constant", first list what each literal bounds and whether raising it changes any outcome; disclose any change in What's new and a QA row.
- Parallel branches collide on QA row ids (two branches both added 7.10 on 2026-11-08). The coordinator reserves the id in each prompt (check `docs/qa-checklist.md` on `next` and every open `work/*` branch), or asks for a block-suffixed id, before dispatch.
- A child branch cut from a parent that then receives fix commits is stale: on 2026-11-08 T-BUG-PROV and T-BUG-SHOPS had to be deleted and recreated after their parents' tier-1 fixes. Cut a stacked branch only after the parent has passed tier 1, and merge parent before child.
- Fresh reviewers caught defects in the lead engineer's own branches twice today (T-CAP: a literal that was a silent clamp elsewhere; T-BUG-GEN: epoch not bumped on every busy start, Create All racing a queued loot fit). Never let the builder's terminal review its own branch, even for a small follow-up.
- A multi-file edit script must write each file right after its own checks pass, or assert everything first and write last; on 2026-11-08 one stale assertion left PLAYBOOK unwritten while the other files were already committed under a message that named it.

- **A cleared browser cache takes the harness with it.** On 2026-11-09 `/root/.cache/ms-playwright` was gone and `shoot.mjs` failed with "Executable doesn't exist ... chromium_headless_shell-1248". From `tools/ui-preview` after the two `npm install` lines: `npx playwright install chromium-headless-shell` restores the build pinned by 1.64.1.
- **A usage limit kills reviews mid-report.** One Haiku wrote "INCOMPLETE (not PASS)" when the account ran out; another terminal's half-done merge branch was left behind. After a limit: respawn the crew, `grep VERDICT` every report dated near the cut, rerun any that is partial, and verify a half-built `work/BATCH-n` yourself (release-check plus the harness) or rebuild it. A handoff file in `/root/sf2e-wt/reports/HANDOFF-<date>.md` written before stopping made the restart a five-minute job.
- **Old-vs-new comparisons need a frozen base.** Tier-1 prompts that import "the base" from `/root/simplySF2e` break when a batch lands on `next` mid-review. Export it once (`git archive <sha> | tar -x -C /root/sf2e-wt/base-<sha>`) and point reviewers there.
- **A guard added for one entry point hides the others.** The first hunt guarded Provider Setup's own connection select against a run in another window; the header selects of the four tool windows, and Provider Setup's Create and Delete, changed the active connection with no such check (found 2026-11-09). When a fix adds a guard, grep for every caller of the function it protects (`selectProviderConnection`, `createProviderConnection`, `deleteProviderConnection`) before closing the finding.
- **A lock set for a whole run blocks the run's own last step.** `#createPending` was set by `#runGeneration` and checked by `#createEncounterActors`, so one-click Generate in Encounter mode built the preview and silently created nothing. No test called `runGeneration` with `create: true`. Every mode's one-click path needs one test through the real app.
- **"A preview exists" is not "this call made a preview".** Generate created the previous Character preview when the new call returned early on an empty prompt. Gate a follow-on step on the return value of the step before it, never on leftover state.

**Release and process**
- A tag pushed with the default `GITHUB_TOKEN` does not fire `push: tags`; releases chain through `workflow_call`. In a reusable workflow, `github.event_name` is the caller's event, so use `inputs.version`. `node --check` never catches these; a `.yml` change needs a real test merge.
- Fresh-context review has caught real bugs many times; a builder's self-report is not verification.
- `hc read` loses a TUI agent's scrollback (the first T1 report on 2026-11-05 was unreadable). Always have agents write reports to files.
- Parallel workers need one worktree each and disjoint files; shared worktrees collided before. Set identity with `git config` in each new worktree.
- `hc read` shows only the visible pane of a TUI agent; `hc send --if idle` refuses a `done` terminal (send without `--if` after checking `hc ls`). If a worker terminal stops on a permission prompt, the coordinator must not answer it; tell JT.
- JT sometimes merges while a review is still running. Say when one is in flight; fixes for a merged PR go in a new PR.
- Keep each file's existing line endings (LF on this VPS clone); `git diff --check` must stay clean.
- `tools/release-check.sh` UI step runs `npm install`, which drops a `--no-save` Playwright; run `node tools/ui-preview/shoot.mjs` directly after `npm install --no-save playwright` if it reports `Cannot find module 'playwright'`.
- The offline class bench (`tools/class-bench/`, fetch then run) builds every class x level against real pack JSON; use it before claiming a PC-pipeline fix works.
- Promoting an existing beta pre-release to stable does not make GitHub recompute Latest (v0.1.4 stayed behind v0.1.3 until `gh release edit v0.1.4 --latest`). `release.yml` now sets Latest on a stable publish when the tag is the highest stable version. Always check `releases/latest/download/module.json` after a stable dispatch.
- Squash merges hide merged branches from `git branch --merged`; match branch tips to merged PR heads through the GitHub API.
- A stacked branch carries its parent's commits: land the parent PR first, or the child PR re-includes the whole parent diff. Rebuild the child branch on the new `main` afterwards so its diff is only the batch.
- Two implementations of the same concern merge **textually clean** and still be wrong. `scripts/ai-transport.mjs` here had a landed Retry-After/jitter path and a branch's network-retry path; the ort merge succeeded, and only reading the merged function showed they composed correctly. Read the merged file, then test it.
- Stray 0-byte untracked files (a killed run's leftovers) block `git merge` with "untracked working tree files would be overwritten" when the branch tracks those paths. Check `git status` before a merge, not after it fails.

- **Watchers on report files, not headings.** A `grep -q "## Fix"` watcher fired on an older heading in the same report; wait on a new commit SHA plus a clean tree (`git status --short` empty), or on the exact heading at line start (`^## Fix$`).
- **A fix commit can land after the integrator merged.** Three times today (U3, U5-SETUP twice) a fix arrived while Sonnet was already integrating; the fix is a second `git merge --no-ff work/<ID>` into the batch branch plus a re-check, never a reset. Prompt integrators to check `git -C /root/sf2e-wt/<ID> log` right before merging.
- **Copy sweeps need a state check per string.** "Press Generate another shop" was false in the state that shows the message (the button reads "Generate shop" there); "Waiting for the AI provider" showed only on Create flows with no AI request. Tier 2 must trace where each reworded string renders before a sweep lands.
- **Visual branches hide behaviour changes.** U4B's "Welcome as a boot sequence" gated Connect behind a tile click (a GM with a saved key lost a step); the coordinator reverted it. Any designer task gets "no behaviour change" spelled out and a tier that diffs the app files against base.
- **New hints need every update path.** U5's visible saved-key hint was correct on render and stale after Load models because `#refreshAfterSave` patched the DOM in place (BATCH-5). When a template gains state-driven markup, grep the app for every in-place DOM update of that region.
- **CSS "no-op" fixes.** `min-width` under a rule that fixes `width` does nothing; a local `--spf-icon-btn: var(--spf-icon-btn-sm)` is invalid until the token exists. Use `width: var(--spf-icon-btn-sm, var(--spf-icon-btn))` so the fallback holds before the shared branch merges.
- **Harness identity.** `SPF_SHOOT_FREEZE=1` makes PNGs stable except a native indeterminate `<progress>` (shadow DOM, not CSS) and occasional `-short` flakes; for "no visual change" proofs compare the rendered `out/*.html` byte for byte and the PNGs only by eye.
- **Stopping a stale subagent.** A finished subagent can be resumed from its transcript view and start burning tokens again; `TaskStop` by its id ends it. Its report lives in the repo docs by then, so nothing is lost.
- **An issued candidate ref is not an index entry.** `candidateRecord` issues `{packId, _id}` only; `entry.system`, `.type` and `.name` are undefined on it. Resolve it with `getIndexEntry(ref)` (compendium.mjs) before reading data, and keep the ref itself for identity. Production always takes the issued path, so a test that builds entries by hand misses this (R3-SPELL, 2026-11-10).
- **A name is not a trait or a slug.** `slugify(name)` gives `ysoki` and `g-folian`; the pack says `ratfolk` and `gfolian`. Read traits from the document and test against every document in the pinned pack (R3-PC).
- **Parallel workers on one file.** Two subagents edited `provider-setup-app.mjs` (save path vs open helper) and two edited `generator-app.mjs` (handlers vs character methods) at once. Naming each worker's methods in both prompts kept the code merges clean; what still broke was a conflict where both changed the same call and a source-scan test in one branch that pinned text the other replaced. Merge one branch at a time and run the all-tests loop after each merge (R4, 2026-11-10).
- **A test that only appends keeps both sides.** When two branches append blocks to the end of one test file, git reports a conflict; keep both blocks and re-add the closing brace that sat outside the conflict (R4 `provider-setup-app.test.mjs`).
- **Ask the data before fixing.** The upgrade-slot "bug" (description never indexed) was real code but changed nothing: sf2e 1.7.0 has no capacity data. A prompt that says "investigate first, then choose (a), (b) or (c)" let the worker report the false alarm and remove the dead code instead of building a parser (R3-SLOTS).
- **A cited table can still be wrong.** `STRIKE_ATTACK.high` at 23/24 was off by one for months under a "CITED" comment. A row whose step pattern breaks is worth one page fetch; pin the corrected cells in `tables.test.mjs` with the URL.
- **Subagent reports are leads.** A worker's "verified" needs a quoted line; the coordinator reads the diff and, for UI, the PNGs. In R3/R4 the read found one stale warning string, one bullet over the word cap after a coordinator edit, and one fixture-only inconsistency.
- **Never symlink the bench cache into a worktree.** A bench run wrote `results.json` through a symlink into `/root/simplySF2e` (gitignored, harmless, but outside the worktree). Copy it.

## 9. Known gaps (by design or deferred)

- **Focus:** a focus-only NPC (no tradition, so no DC) is unsupported. The NPC pool size (spell count, max 3) is a module default.
- **Item Forge passives** exist only for kinds with a published `sf2e.equipment` exemplar: item bonus, resistance, sense. Weakness, immunity and speed are hidden. No sf2e item uses an `etched-onto-*` usage.
- **Upgrades:** only `installed-in-a-weapon` / `installed-in-armor` usages are offered (`runes.mjs`, cited to `usage.ts`). Upgrade slot counts are **uncited and on hiatus** (`defaultUpgradeSlots` in `runes.mjs`: weapon 1 / armor 0; sf2e 1.7.0 declares no upgrade capacity in data, and only two armors state a slot in prose, checked 2026-11-10). Prerequisites and exclusivity are not validated; shields and ammo are out of scope.
- **PC skills/feats:** unknown grant timing and missing class data are warned, not inferred. A feat slot never takes a feat the ancestry, heritage, background or class path already grants (R4-PC, 2026-11-10; a multi-take feat needs a second copy added by hand); new Lore replacements stay manual; not live-tested. Class-path details (Operative specialization, Sniper; Solarian has no `item:tag` path) are in `class-paths.mjs`; Mystic/Witchwarper casting (spontaneous, 3 slots per rank, 5 cantrips, 10th rank at 19) and Technomancer (prepared arcane, base 2 slots) in `pc-tables.mjs`. Mechanic's Drone exocortex needs a companion the module does not create; the GM gets a whisper after Create. Exocortex and Programming Language are ordinary `item:tag` class paths. Free Archetype slot placement and ordinary prerequisites are checked (`pc-prerequisites.mjs`); a full prerequisite graph is unbuilt.
- **Technomancer spell database:** a high-level database fills only as far as the fixed spell candidate cap allows (12 per rank, 96 total; PLAYBOOK §8 says ceilings are never raised to fit). A shortfall warns at Create.
- **Rarity cap** covers ancestry/background/heritage only, by design.
- **Multiclass:** the GM picker and AI choice require Free Archetype; dedications and caster spell lists shipped in #70. A full prerequisite graph remains deferred. Live verification is still needed.

- **Ability fills/templates:** filled glossary values, Area Blast and Aura use the creature's base level; Elite/Weak leaves ability text unchanged (re-level rebuilds module-built abilities; older actors without the provenance flag are not rebuilt). Damage from the Area Damage table is approximate (published creatures tune per creature; 41% exact). Rupture is the Area Damage average (weakest fit). Area Blast has no burst shape (no clean published scaffold) and no riders; auras apply nothing automatically (the GM applies the save result). Single-ability reroll skips the resolve-time dry run (build backstop still guards). Two drafts with one glossary name merge into the first.
- **Cost:** manual prices are per browser (the connection bank is client-scoped). A run whose only usage is total-only with manual prices shows no cost line at all (`runCost` returns the none shape, pinned by `cost.test.mjs:101`); `cost.mixedUsage.test.mjs` (2026-11-08) covers the mixed split + total-only shapes and found no misread. JT may prefer a "partial" flag there; that is a separate small task.
